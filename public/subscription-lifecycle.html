展开完整 10 阶段时序

    第二次扣款 · 从账期到权益

    首购已授权，下月由原 PSP 到期收款。 以无试用、无设置费的月付套餐为例。首扣属于第 1 期，下月续费属于第 2 期。余额不足后再次尝试，仍是在收第 2 期的账款。应用的定时任务负责对账和通知。

    PayPal · 原 Subscription 按 Plan 续费

    1. 首购　保存商户账户、subscription_id 和 plan_id。买家在 PayPal 批准自动付款，由 PayPal 管理该订阅的付款来源。
    2. 到期　PayPal 按 billing_cycles 尝试收款。后端可用 GET /v1/billing/subscriptions/{id} 读取 billing_info.next_billing_time 作为显示和对账参考。
    3. 结算　成功收到 PAYMENT.SALE.COMPLETED。核实 Sale、订阅与款项所覆盖的账期。补收可能覆盖历史欠款，按分配结果更新权益。

    Stripe · 为新周期生成新 Invoice

    1. 首购　通过 Checkout 保存订阅的付款方式。自建流程也可在取得用户未来扣款授权后用 SetupIntent 准备 off-session 付款方式。保存渠道引用。
    2. 到期　Stripe 按账期生成新 Invoice，典型续费为 billing_reason=subscription_cycle。账单 finalize 后，charge_automatically 用适用的默认付款方式发起 off-session 扣款。
    3. 结算　收到 invoice.paid 后，核实结清方式、账单行和服务期。重试沿用本期 Invoice。遇到异步处理中状态时，等待最终结果或查原账单。

    Adapter 的交接点　验签 → 持久化 Inbox → 用原 PSP 查询补足证据 → 把 Sale 或 Invoice 归一成结算事实 → 事务内更新账期与权益。用 (subscription_id, billing_period_id, credit_type) 防止重复发放。账单事件可能乱序，后到的旧失败不能抹掉已确认结算。

    Billing 模式怎么区分

    怎么收费

    固定价、按席位或按用量决定应收金额。Stripe 固定价用 recurring Price，按席位用订阅项的 quantity。按用量计费先记录和汇总使用量，再生成账单。PayPal 本页的例子使用 Plan 的 billing_cycles、定价和试用设置。

    怎么收钱

    Stripe collection_method=charge_automatically 自动尝试扣款。send_invoice 发账单并设置付款期限，由客户付款。PayPal 本例使用买家批准的自动付款。

    怎么计算或调整账单

    Stripe 的 billing_mode=classic 或 flexible 影响账单行为，例如改价时如何计算比例抵扣。PayPal 的 payment_preferences 控制重试失败后的欠款补收和暂停阈值。

    续费失败怎么处理

    卡没钱 · 余额不足

    Stripe　invoice.payment_failed 后查可用的付款错误信息，例如 insufficient_funds。提醒用户补足余额或换卡。可重试时交给 Smart Retries 或自定义计划处理同一张 Invoice。PayPal　收到 BILLING.SUBSCRIPTION.PAYMENT.FAILED 后查询订阅与可用的失败详情。按原计划重试，核对失败计数和欠款。渠道未提供具体原因时，内部记录普通支付失败。

    卡不安全 · 风控拦截、挂失或硬拒绝

    处理　Stripe 可能报告 fraudulent、stolen_card 或其他拒绝。内部记录有限的诊断信息，对客户给通用拒绝提示，引导换卡或联系发卡行。PayPal 钱包路线由 PayPal 管理风控。只使用它返回的失败信息。停止应用发起的盲重试，保留原订阅归属。

    卡过期或没有默认卡 · 更新付款方式

    Stripe　用 POST /v1/billing_portal/sessions 引导客户更新付款信息，或用 SetupIntent 收集新卡。查明是哪一层默认卡失败，若订阅设置了 default_payment_method，需核对并按授权更新该字段。只改 Customer 默认卡可能仍会重试旧卡。PayPal　引导买家在其自动付款设置中修改可用付款方式，再查原订阅结果。

    需要 3DS · 用户必须回来完成认证

    Stripe　处理 invoice.payment_action_required 或已确认的 requires_action，通过原账单的 hosted_invoice_url 引导客户完成适用的认证。保存好付款方式仍可能需要补认证。PayPal　按渠道提供的客户动作或原订阅批准流程引导用户。两边都等最终结算再更新新一期权益。

    账单未定稿、扣款超时或仍在处理中

    未定稿　收到 invoice.finalization_failed 时用 GET /v1/invoices/{id} 查 last_finalization_error，补齐资料后等自动定稿，或在草稿符合条件时调用 POST /v1/invoices/{id}/finalize。结果未知　保存原尝试和幂等键，查询原渠道 Invoice 或订阅交易，等待或对账。PayPal 交易用 GET /v1/billing/subscriptions/{id}/transactions。确认原尝试结果后才能决定是否发起新操作。

    客服手动补收 · 如何避免撞上自动重试

    同一账期只允许一个业务补收任务在途。操作前查询原 PSP 的账款和未决付款。应用内锁只能限制自己的补收任务，自动重试仍由 PSP 调度。若不确定是否会撞上自动重试，等待原渠道结果或让用户在原账单页完成付款。Stripe 可在允许时对现有未结清账单调用 POST /v1/invoices/{id}/pay。PayPal 可在支持条件下对已确认欠款调用 POST /v1/billing/subscriptions/{id}/capture，使用 OUTSTANDING_BALANCE。符合接口条件时使用幂等键，完成后仍按终态与账期发放。重试耗尽后按产品宽限期处理权益。

    官方资料　Stripe 收款方式 · Classic 与 Flexible · SetupIntent · 卡拒绝码 · 客户门户 API · Invoice Pay API · PayPal 订阅查询 · PayPal 自动付款设置

    授权、扣款和 Webhook 的关系

    PayPal · 买家授权后按计划计费

    1. 复用 Product 和 Plan，创建订阅并引导买家批准 approve 链接。
    2. 收到激活通知或查询到 ACTIVE，记录订阅状态。试用、延迟开始和设置费可改变首笔实扣时间。
    3. 根据计划扣款，成功时收到 PAYMENT.SALE.COMPLETED。每笔 Sale 都要关联订阅并判断款项归属。
    4. 后续按周期扣款。失败可重试、累积欠款、暂停，用 auto_bill_outstanding 配置自动补收，用 payment_failure_threshold 配置暂停阈值。符合条件时也能通过 capture 补收。

    Stripe · 以 Invoice 驱动周期计费

    1. 复用 Product 和 recurring Price。托管方式创建 Checkout Session，也可给已有 Customer 直接建立 Subscription。
    2. 在常见的自动收款流程中，首次 Invoice 生成并 finalize，然后尝试收款。需要认证或异步确认时继续等最终状态。
    3. invoice.paid 表示账单已结清。核对结清方式、账单行和订阅状态，再按业务规则发权益。
    4. 续费生成新的 Invoice。失败按配置尝试恢复，支付和订阅状态分别更新。

    投递可以乱序或重复。 浏览器回跳只更新 UI。后端先验签并持久化 Inbox，按 PSP 事件 ID 去重，缺失或矛盾时查原渠道，再由 Worker 应用业务状态和权益。

    Adapter 统一什么

    操作契约

    同一个 createCheckout(intent) 可返回审批 URL，或返回需要认证、等待确认的结果。改套餐能力可以声明「需重新同意」和实际生效日期。

    状态与证据

    分别保存原始订阅状态、账单或交易证据与内部权益。PayPal ACTIVE 可同时有未解决的欠款，内部 PAST_DUE 由自己的策略推导。

    两层幂等

    Inbox 按渠道账户和事件 ID 去重。结算证据保留 invoice 或 sale 的类型和 ID。权益按内部账期守住唯一性，避免补收或拆单引起重复发放。

    同一份内部契约

    Stripe 的 Invoice ID 和 PayPal 的 Sale ID 作为带类型的证据引用保留。允许一个收款证据核销多个账期。

  provider: "paypal" | "stripe"
  accountId: string
  subscriptionRef: string
  evidence: { kind: "sale" | "invoice"; id: string }

}

const verified = await adapter.verifyWebhook(rawBody, headers)
await inbox.storeOnce(verified) // UNIQUE (provider, account_id, event_id)

// Worker 从持久化 Inbox 读取，按原 PSP 查询并验证
const fact = await adapter.normalize(inboxEntry)
const periods = await billing.resolveCoveredPeriods(fact)
await db.transaction(async tx => {
  await tx.recordBillingFact(fact)
  if (fact.outcome === "settled") {
    for (const period of periods) {
      await tx.ledger.grantOnce(period, "monthly_credits")
    }
  }
  if (fact.outcome === "reversed") {
    await tx.ledger.adjustOnce(fact, periods)
  }
  await tx.inbox.markProcessed(inboxEntry)
})
// UNIQUE (subscription_id, billing_period_id, credit_type)

    异常与补偿

    买家退出、回跳成功，或创建请求超时

    未完成批准时保留待确认意图，并按超时策略关闭本地入口。创建请求超时属于 UNKNOWN，使用原渠道幂等键重试或查询原尝试。确认没有有效扣款风险后才决定是否新建尝试。

    重复、丢失和乱序 Webhook

    同事件入 Inbox 一次，同一账期发放一次。接到旧失败通知时，查询原账单、交易和订阅，避免覆盖已确认的成功。定期拉 Stripe Invoice 和 PayPal 订阅交易列表，补齐缺失记录。订阅状态变化也需要单独追踪。PayPal 官方说明，未获 HTTP 2xx 时，Webhook 最多在 3 天内重投 25 次。该窗口与订阅扣款重试无关。

    恢复、取消、退款和权益归属

    本地宽限期与 PSP 重试窗口独立。取消按已付服务期决定何时停权益。退款或撤销关联原付款证据，按影响的账期和数量调整账本。部分退款由业务规则决定如何处理。
