    授权、扣款和 Webhook 的关系

    PayPal · 买家授权后按计划计费

    1. 复用 Product 和 Plan，创建订阅并引导买家批准 approve 链接。
    2. 收到激活通知或查询到 ACTIVE，记录订阅状态。试用、延迟开始和设置费可改变首笔实扣时间。
    3. 根据计划扣款，成功时收到 PAYMENT.SALE.COMPLETED。每笔 Sale 都要关联订阅并判断款项归属。
    4. 后续按周期扣款。失败可重试、累积欠款、暂停，用 auto_bill_outstanding 配置自动补收，用 payment_failure_threshold 配置暂停阈值。符合条件时也能通过 capture 补收。

    Stripe · 以 Invoice 驱动周期计费

    1. 复用 Product 和 recurring Price。托管方式创建 Checkout Session，也可给已有 Customer 直接建立 Subscription。
    2. 在常见的自动收款流程中，首次 Invoice 生成并 finalize，然后尝试收款。需要认证或异步确认时继续等最终状态。
    3. invoice.paid 表示账单已结清。核对结清方式、账单行和订阅状态，再按业务规则发权益。
    4. 续费生成新的 Invoice。失败按配置尝试恢复，支付和订阅状态分别更新。

    投递可以乱序或重复。 浏览器回跳只更新 UI。后端先验签并持久化 Inbox，按 PSP 事件 ID 去重，缺失或矛盾时查原渠道，再由 Worker 应用业务状态和权益。

    Adapter 统一什么

    操作契约

    同一个 createCheckout(intent) 可返回审批 URL，或返回需要认证、等待确认的结果。改套餐能力可以声明「需重新同意」和实际生效日期。

    状态与证据

    分别保存原始订阅状态、账单或交易证据与内部权益。PayPal ACTIVE 可同时有未解决的欠款，内部 PAST_DUE 由自己的策略推导。

    两层幂等

    Inbox 按渠道账户和事件 ID 去重。结算证据保留 invoice 或 sale 的类型和 ID。权益按内部账期守住唯一性，避免补收或拆单引起重复发放。

    同一份内部契约

    Stripe 的 Invoice ID 和 PayPal 的 Sale ID 作为带类型的证据引用保留。允许一个收款证据核销多个账期。

await db.transaction(async tx => {
  await tx.recordBillingFact(fact)
  if (fact.outcome === "settled") {

      await tx.ledger.grantOnce(period, "monthly_credits")
    }
  }
  if (fact.outcome === "reversed") {
    await tx.ledger.adjustOnce(fact, periods)
  }
  await tx.inbox.markProcessed(inboxEntry)
})

    异常与补偿

    买家退出、回跳成功，或创建请求超时

    未完成批准时保留待确认意图，并按超时策略关闭本地入口。创建请求超时属于 UNKNOWN，使用原渠道幂等键重试或查询原尝试。确认没有有效扣款风险后才决定是否新建尝试。

    重复、丢失和乱序 Webhook

    同事件入 Inbox 一次，同一账期发放一次。接到旧失败通知时，查询原账单、交易和订阅，避免覆盖已确认的成功。定期拉 Stripe Invoice 和 PayPal 订阅交易列表，补齐缺失记录。订阅状态变化也需要单独追踪。PayPal 官方说明，未获 HTTP 2xx 时，Webhook 最多在 3 天内重投 25 次。该窗口与订阅扣款重试无关。

    恢复、取消、退款和权益归属

    本地宽限期与 PSP 重试窗口独立。取消按已付服务期决定何时停权益。退款或撤销关联原付款证据，按影响的账期和数量调整账本。部分退款由业务规则决定如何处理。

    API 对照

    创建

    PayPal · POST /v1/billing/subscriptionsStripe · POST /v1/checkout/sessions 或 /v1/subscriptions

    升降级

    PayPal · POST /v1/billing/subscriptions/{id}/reviseStripe · POST /v1/subscriptions/{id}

    暂停与取消

    PayPal · POST .../{id}/suspend、/activate、/cancelStripe · POST /v1/subscriptions/{id} 设置期末取消，或 DELETE /v1/subscriptions/{id} 立即取消

    对账与补收

    PayPal · GET .../{id}/transactions，POST .../{id}/captureStripe · GET /v1/invoices?subscription={id}，POST /v1/invoices/{id}/pay
