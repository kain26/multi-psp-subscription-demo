容错机制与切换条件
Timeout
限制本地等待时间。请求已发出且结果不确定时，将尝试标为 UNKNOWN 并查原 PSP。
Circuit Breaker
渠道故障率过高时快速拒绝新请求。示例为 60 秒内至少 20 次且故障率达到 50%，冷却 30 秒后最多放行 3 个安全探测。
Bulkhead 与限流
分别隔离 Stripe 和 PayPal 的并发槽位及连接池，再用限流控制单位时间内的请求量。
Fallback
发送前可选兼容备用渠道。发送后先核对原尝试。只有确认无有效交易且业务策略允许，才建立新尝试。

多实例 Node.js 部署按 PSP、商户账户和操作聚合指标，共享或协调熔断状态及探测租约。连接池与并发槽位可在实例内隔离，需全局硬上限时再加分布式配额。追踪 PSP、Attempt 和账期，保持配置可版本化。

已有订阅的 PSP 迁移单独规划授权、支付凭证、订阅映射和账期切换，核对旧渠道未决扣款后再启用新续费。

Adapter

统一 Checkout、状态查询和事件语义。各渠道的能力、标识和幂等范围留在 Adapter 内。

Router

按国家、币种、支付方式、能力和健康度做初始选择。已经发出的尝试保留渠道归属。

State Machine

一次扣款、周期账单、长期订阅和产品权益各自迁移。续费失败可以进入宽限期。

Idempotency + Reconciliation

用持久化唯一约束阻止重复效果，定期查渠道状态和权益账本补齐遗漏。
